# Agent notes for this blog

- **Everything about a post lives in its frontmatter.** The home page, the blog index and the post page all read the same fields: `title` (one short title, used everywhere), `subtitle` (optional, one short line), `stat` (the one headline number), `statLabel`, `figures`. One field per fact: no long and short versions of the same thing. Never add a per-post table to a page; a new post must show up everywhere with no other file changed.
- **Posts about work stay high level.** This repo is public and work code is private: no repo, product, package, file or colleague names, and no work code or config. Counts, timings and the general idea are fine. That applies to plan and draft files here too.
- Figures follow DESIGN.md: titles above, labels on the marks, sources as footnotes or links next to what they back up, never a separate sources section.
- **Posts read like Colin talking, not a report.** Results the reader can scan first, then in the first person: the hook, the problem, the fix, in that order. Model the voice on how he writes in chat and on the easyJet post: "I kind of assumed", "to be honest", "as far as I can tell", "it should've been that way from the start". No absolutes and no invented consensus ("everyone says", "all of the speed"). Hedge where he would. Sentences run on the way he talks, joined with "and" and "so", with softeners like "purely", "to do with", "actually"; never clipped fragments ("Not once. 1,370 times.") and no sentence-length cap. Active voice, no semicolons. Headings are questions or dates, never "Background" or "Results" style. When he asks for versions, make them distinct in opening, structure, figures and depth on the same facts.
